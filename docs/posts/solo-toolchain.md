# 一个人怎么活成一支团队：独立开发者工具链

我是独立开发者：一个人做产品、写代码、运维、做内容、谈事情。做的东西还不少——视频拆解系统、推广申请处理 Agent、抖音数据监控工具、博客、给家人做的 app。

一个人不是"什么都做一点"，而是**把本该是多个人的岗位，用工具和流程补上**。这篇是我现在在用的整套工具链，按"岗位"拆开讲。

## 算力岗：本地 + 云端分层

强算力走云端，本地不跑大模型——不是不想，是成本算不过账。

- **本地 Ollama**：`qwen3-vl:8b` 做视觉解析和 OCR（拿手绘的板栗 logo 说，识别这类图形它够用），`qwen2.5:14b` 做文本拆解。跑在双服务器上：i7-12700KF + RTX 4070 12GB 负责采源拆解，A10 24GB 负责生成。
- **云端 DeepSeek API**：需要大模型硬推理的时候调云端，按量付费。预算敏感，所以默认走免费档，把付费能力做成"开关"而不是"必选"。

一句话原则：**能本地便宜的绝不上云，要上云就按量省着用。**

## 工程岗：能跑还不够，要能交付

一个人最怕的不是写不出来，是写出来**没法证明是对的**。我的武器：

- **测试**：推广申请处理 Agent 有 26 个单测（提取准确率跑到了 100%），抖音数据监控工具 38 个单测。单人项目也要测试——因为没有人给你 review，测试就是你的第二个同事。
- **CI/CD**：GitHub Actions 自动部署。push 之后 1-2 分钟线上生效，不用记部署命令。
- **文档体系**：项目文档按 00-13 编号，每篇记"断点续传"——隔三个月回来，靠文档就能接着写，不靠记忆。

## 数据岗：一切进数据库

爬虫、监控、拆解，所有数据落到 PostgreSQL。7 个业务库、每库 5 张表（元数据/作者/指标/帧/评论），统一的数据字典，27 个字段有明确来源。

单人开发更要"表结构即契约"——不然三个月后自己都看不懂自己写的代码。

## 内容岗：博客 + 公众号 + 社交媒体

- 博客 VitePress + GitHub Pages，文章即 markdown，push 即发布
- 社交分享用品牌分享卡（og:image），分享出去的每一眼都是完整品牌
- 选题来自项目踩坑——写博客不额外消耗精力，把踩过的坑顺手记下来

## 协作岗：飞书就是我的"同事"

- 飞书机器人（推广申请处理 Agent）在群里值班：@ 它发申请，它提取、发确认卡片、写表格，全程无人值守
- 消息指纹 + 状态机做幂等，重复消息直接拦截，不重复烧 LLM 费用
- Master-Sub 架构：一个主机器人分发，多个子机器人干活

## 一个人最重要的两件事

1. **把决策变成开关**。免费档/付费档、模型档位、本地/云端——全部抽象成配置，业务代码不认识厂商。改档位不改代码。
2. **把经验变成文档**。文档不是写给别人的，是写给三个月后的自己。每个坑记下来，就是给未来的自己省时间。

一个人活成一支团队的核心不是"干得多"，是**让每个岗位都有可复用的系统**。系统在，人换不换、记不记得住，都不重要。
