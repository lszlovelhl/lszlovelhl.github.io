# 抖音数据监控工具：从爬虫到告警的完整工程

抖音数据监控工具是我的转型期作品之一，也是"从爬虫到 Agent"路线上承上启下的一环。它不是一个爬虫 demo，而是一个**完整工程**：Playwright 采集 + FastAPI 接口 + SQLite 存储 + 定时任务 + 告警闭环，38 个单测。这篇拆开讲。

## 架构总览

```
┌─────────────┐   ┌──────────────┐   ┌──────────────┐
│ Playwright  │ → │  FastAPI     │ → │  SQLite      │
│ 采集层      │   │  接口层      │   │  存储层      │
└─────────────┘   └──────┬───────┘   └──────┬───────┘
                         │                  │
                         ▼                  ▼
                    ┌────────────┐   ┌────────────┐
                    │ 规则判定   │ → │ 告警通知   │
                    │ 阈值/关键词│   │ 飞书/微信  │
                    └────────────┘   └────────────┘
```

四个层次：**采集 → 接口 → 判定 → 告警**。每一层都可以独立替换——这是单人工程最重要的设计：改了采集层不碰接口层，换了存储不碰业务。

## 采集层：Playwright，对抗不稳定

抖音页面是动态渲染的，requests 拿不到完整数据，所以用 Playwright 驱动真实浏览器。

关键工程点：

- **选择器容错**：页面结构说变就变，用多级选择器降级（首选稳定属性 → 次选文本匹配）
- **限速与节流**：不触发风控的采集节奏，失败自动退避
- **会话复用**：浏览器实例复用，不每次冷启动
- **数据字典先行**：27 个字段（标题、作者、点赞/评论/收藏/分享、发布时间、标签、是否 AI 生成……）每个都有明确 DOM 来源

爬虫最大的敌人不是反爬，是**自己先崩**。所以采集层要能自愈：异常捕获 → 重试 → 告警，而不是静默失败。

## 接口层：FastAPI，把能力暴露出去

采集是内部动作，对外用 FastAPI 统一出口：

```python
@app.get("/api/videos/{vid}")
def get_video(vid: str):
    return get_video_from_db(vid)
```

为什么要有接口层？

- **解耦**：上层（监控、分析、前端）只认识接口，不认识 Playwright
- **可测试**：接口是稳定的测试面，38 个单测主要打在这一层
- **可复用**：同一个工具后面还能长出新功能（拆解、告警），不用重写

## 判定层：监控不是"抓下来"，是"看出问题"

数据落到 SQLite 之后，真正值钱的是判定逻辑：

- **阈值监控**：互动数据（点赞/评论/收藏/分享）超过/低于阈值 → 触发
- **关键词监控**：标题、标签命中关键词 → 触发
- **趋势判定**：完播率公式筛选、互动率异常变化 → 标记

判定规则要**可配置、可解释**：为什么这条触发告警，规则本身要能回答，而不是黑盒。

## 告警层：把"问题"变成"通知"

监控闭环的最后一环：不是存下来等人看，而是**主动推给该知道的人**。

- 触发条件 → 推送到飞书（机器人消息）
- 告警带上上下文：视频链接、关键指标、触发原因
- 去重：同一视频同一原因只告警一次（幂等）

告警没去重的后果：一个阈值误报，群里刷屏 50 条，第二天就被静音——告警就死了。

## 单测：38 个测试证明它活着

单人开发的证明方式：**单测**。38 个单测覆盖：

- 采集数据 → 接口返回（mock 浏览器，不真跑）
- 判定逻辑 → 阈值/关键词正确触发
- 告警去重 → 重复触发不重复推送
- 数据落库 → 幂等写入

`pytest` 跑完绿了，才敢说"这功能是真的"，不是"感觉能跑"。

## 踩过的坑

1. **页面结构变了，选择器全废**——所以选择器要分层降级，且采集失败要告警而不是静默
2. **一次采集重复入库**——数据表加唯一键，写入 `ON CONFLICT DO NOTHING`
3. **定时任务跑挂没人知道**——加心跳告警：任务"该跑没跑"也要告警

## 总结

"监控工具"四个字，做的是四件事：**采得到、存得住、看得出、喊得响**。每一件都不难，但合在一起是一个完整工程。它给我的真正回报是：证明了**一个人能把"数据获取 + 分析 + 服务化"走通**——这条路后来直接通向 AI 拆解系统和 Agent。
