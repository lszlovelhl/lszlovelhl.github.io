# 准确率 100% 不是玄学：提取器评测怎么做

推广申请 Agent 的提取器，README 里写着"双模式 P / R / F1 均 100%"。这个数字不是拍脑袋，是 `tools/eval_extractor.py` 在真实历史确认记录上跑出来的。

## 为什么必须评测

提取器有两套路径：**规则正则**（快、准、零成本）和 **LLM 兜底**（处理口语化文本）。问题在于——"感觉准确"没有任何意义。

- 规则改一个正则，可能让 30 条历史记录集体解析失败
- LLM 换模型/换 prompt，输出字段名一漂移，提取就整体失效（见《LLM 兜底为什么"看似成功却返回空"》）
- 没有基线，所有"优化"都是盲改

评测就是把"感觉"变成"数字"。

## 评测怎么设计

**数据集**：真实历史确认记录（人工确认过的事实），不是自己编的样例。人工确认记录 = 权威标注，不需要另请人标数据。

**双模式**：同一批输入，分别跑规则路径和 LLM 路径，各自算指标——这样能看出哪条路径拖后腿。

**指标**：按提取字段逐项算 P / R / F1。

- Precision（精确率）：提取出来的里，多少是对的
- Recall（召回率）：该提取的里，多少被提出来了
- F1：两者调和平均

```bash
python tools/eval_extractor.py --mode rule     # 规则模式评测
python tools/eval_extractor.py --mode llm      # LLM 模式评测
```

评测报告落盘 `tools/eval_report.md`，每次改动可对比。

## 100% 是怎么来的

两条路径在真实数据上分别达到 100%，靠的是：

1. **规则覆盖确定性场景**：金额、笔数、日期、档位这些格式固定的字段，正则比任何模型都稳
2. **LLM 只兜口语化**：规则解析失败的才交给 LLM，且字段名容错映射兜住模型输出漂移
3. **评测驱动修复**：先跑评测看哪里漏，再针对性改规则，而不是凭感觉调

## 收获

"准确率 100%"写在 README 上是有底气的——因为它是**可复现的评测结果**，不是自夸。面试官问"你怎么知道它准确"，回答是：给我 5 分钟跑一遍 eval，数据说话。

> 面试可展开：为什么不用大模型做全部提取？——评测会告诉你答案：规则路径 100% 且零成本，LLM 是兜底不是主力，这叫把确定性留给规则、把不确定性留给模型。
