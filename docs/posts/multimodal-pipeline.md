# 多模态拆解管线：Whisper 转写 + 抽帧视觉理解

拆爆款视频，光看字幕远远不够。镜头语言、画面节奏、BGM 卡点都是爆款密码。帧间的拆解管线用两条腿走路：**音频轨转写 + 关键帧视觉理解**，最后在时间轴上对齐。

## 抽帧策略：密度按视频时长自适应

视频长度 3~180 秒不等，抽帧策略必须跟着走：

- 按 0.5~1 秒间隔截取关键帧
- 长视频封顶 180 帧（控制成本和时延）

帧抽太稀，细节丢了；抽太密，视觉理解调用量大增。密度就是"拆解粒度 × 成本"的平衡点。

## 筛选门槛：先过滤，再拆解

不是所有视频都值得拆。拆解入口用**互动数据公式**做门槛（完播率、点赞密度等），先排除低质内容和 AI 生成的水视频——拆解算力只花在值得拆的爆款上。

## 视觉特征：两段式

1. **特征提取**：后端用 MobileNet 等轻量模型提视觉特征入库——轻、快，支撑检索和聚类
2. **语义理解**：关键帧交给视觉大模型（Qwen VL / GLM-4V 档位）做语义级理解——"这里为什么火""镜头怎么切的"

轻量特征管"像不像"，视觉 LLM 管"为什么"，各司其职。

## 时间轴对齐：转写和抽帧要能对上

拆解最麻烦的是**对齐**：转写出的台词、抽帧出的画面、BGM 的卡点，必须落在同一条时间轴上，才能拼出"第 12 秒的钩子 + 卡点音效 + 快速转场"这种完整证据链。这一层用确定性代码做时间锚点对齐，不让 LLM 编时间。

## 为什么这套管线能讲

它把一堆"听起来很 AI"的事拆成了可执行、可调优、可计成本的工程步骤——面试官问多模态，你能从抽帧密度、特征 vs 语义、时间对齐讲到成本控制，这就不是概念而是工程。
