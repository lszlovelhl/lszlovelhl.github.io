# 大模型 API 成本控制实战：从免费档到按量付费

独立开发者用大模型，最大的焦虑不是效果，是**账单**。我做过一个视频拆解系统，如果全走付费 API，单视频拆解成本可能赶上一条抖音广告的投放费。这篇讲我怎么把成本压下来，原则是什么。

## 原则一：免费档是默认档，付费是开关

我的产品默认 `billing_enforced=false`——也就是说，免费档是产品的默认状态，付费能力只是代码里一个开关。

为什么反着来？因为**成本上限是产品设计的一部分**，不是事后的运维问题。先定"最贵能花多少"，再设计功能，比功能做完再抠成本健康得多。

具体做法：模型调用走一个网关层，业务代码只认"档位"（免费档 / 标准档 / 高级档），不认厂商。换模型、换价格，只改配置，不动业务代码。

## 原则二：能本地便宜的，绝不上云

我有一套双服务器方案：

- **RTX 4070（12GB）**：`qwen3-vl:8b`（Q4_K_M，约 5.5GB）做视觉解析 + 字幕 OCR，`qwen2.5:14b`（Q4_K_M，约 9GB）做文本拆解。显存 14.5GB 超了，靠 layer offload 到 CPU 硬跑。
- **A10（24GB）**：`qwen3-vl:8b`（Q4_K_S）+ `qwen2.5:32b`（Q4_K_M，约 20GB），全部 GPU 驻留，支持岗位并行。

本地部署的吞吐量对比（8 小时批量）：

| 服务器 | 单视频耗时 | 日吞吐 |
|--------|-----------|--------|
| 4070（串行十岗位） | 3-5 分钟 | ~120 条 |
| A10（并行十岗位） | 1.5-2.5 分钟 | ~240 条 |

结论：能本地跑的量，本地跑；只有本地扛不住的硬推理，才花 API 的钱。

## 原则三：别让重复调用烧钱

最贵的调用是**无意义的调用**。两个杀手：

1. **重复消息**：推广申请处理 Agent 在飞书群里值班，用户把消息复制粘贴发两遍，或者机器人网络重试导致同一消息投递两次——每次都调 LLM 提取 = 白烧双倍费用。
   解法：消息文本做 MD5 指纹，状态机三态流转（pending / confirmed / rejected）。重复提交直接拦截：
   ```python
   if rec.get("status") == "confirmed":
       return {"duplicate": True, "message": "该申请已处理并写入表格"}
   ```
2. **失败的调用**：LLM 偶尔返回空字段或异常格式，如果不校验就重试，会一直烧钱直到"成功"。解法：重试要带退避（指数退避 + 抖动），并且要设置上限；调用前先做参数校验，调用后做返回校验，把"注定失败的调用"挡在门外。

## 原则四：能白嫖的尽量白嫖

- 免费额度认真用：各家的免费档、学生档、开发者额度，该薅就薅。
- OCR 用本地开源（PaddleOCR 优先、EasyOCR 兜底、视觉大模型当最后手段）——字幕区域裁剪到画面底部 1/4，跳帧加速（每 2 帧取 1 帧），编辑距离去重（`Levenshtein < 0.2` 视为重复字幕），OCR 成本接近零。
- 视觉特征提取用 MobileNetV3-Small（CPU 就能跑），不需要大模型。

## 一个真实账单的拆解

视频拆解系统单视频的成本结构（全部本地跑时）：

| 阶段 | 成本 |
|------|------|
| 抽帧 + 特征提取（MobileNet，CPU） | 0 |
| 字幕 OCR（PaddleOCR 本地） | 0 |
| 四维分段（余弦相似度，CPU） | 0 |
| 情绪/动作/音频分析（本地 VL） | 0 |
| 十岗位拆解（本地 LLM） | 0 |
| 云端兜底推理（超出本地能力的） | 按量，极少 |

**本地方案让单视频边际成本趋近于零**，这是一个人做内容工业化系统能成立的前提。

## 总结

成本控制不是省钱的技巧，是**架构决策**：

1. 免费档是默认，付费是开关
2. 本地便宜的绝不上云
3. 幂等 + 校验挡住无意义调用
4. 开源工具白嫖优先

独立开发者的每一分算力都花在刀刃上——刀刃之外，能省则省，能白嫖白嫖。
