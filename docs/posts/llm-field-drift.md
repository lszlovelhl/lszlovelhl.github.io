# LLM 兜底为什么"看似成功却返回空"：字段名漂移与 Schema 校验

## 现象

推广申请处理 Agent 采用"规则正则优先 + LLM 兜底"双层提取。规则不命中的口语化文本：

> 麻烦处理下：小美博主垫付了350块，说是买推广用，还有大强哥要充抖加200，都报一下

规则提取失败 → 进入 LLM 兜底。日志显示 LLM 调用成功、返回了 JSON，但最终 `details=[]`——**一条明细都没留下**，用户以为处理了，其实什么都没提取到。这是最危险的失败模式：不报错，静默丢弃。

## 根因：模型"自由发挥"的字段名

直接看 LLM 原始返回：

```json
{
  "报销申报明细": [
    { "相关方": "小美博主", "金额": 350, "资金性质/用途": "垫付购买推广费用" },
    { "相关方": "大强哥", "金额": 200, "资金性质/用途": "充值抖加费用" }
  ]
}
```

提示词要求输出 `app_type / blogger_name / amount`，但模型用了一套自己的命名：**"相关方"→blogger_name、"资金性质/用途"→app_type、"金额"→amount**。系统按约定字段做合法性校验（类型枚举 / 金额正数 / 博主非空），字段对不上 → 全部 `continue` 丢弃 → 空结果。

## 修复：三层防御

**1. 提示词强化字段约束**：明确"必须严格使用这些字段名，禁止改名、禁止嵌套、禁止额外字段"，并给输出示例。

**2. 字段名容错映射**（关键）：与其赌模型守规矩，不如兼容它的常见漂移：

```python
FIELD_ALIASES = {
    "app_type":     ("app_type", "申请类型", "类型"),
    "blogger_name": ("blogger_name", "博主名", "达人", "相关方", "账号", "抖音昵称", "昵称"),
    "amount":       ("amount", "金额", "费用", "价格", "款额"),
    "payer":        ("payer", "支付人", "打款人", "付款方"),
    "apply_date":   ("apply_date", "申请日期", "日期", "申报日期"),
}
```

**3. 类型推断兜底**：`app_type` 从"资金性质/用途"等自由字段的关键词推断（含"垫付"→advance_payment，含"抖加/dou+"→douyin_ad），再退一步从原文判断。

## 顺带发现：LLM 兜底根本没接入主流程

排查中另一个更隐蔽的问题——`extract_with_fallback` 方法写了，但主流程调的是纯规则 `extract()`，**LLM 兜底从未被执行过**。这种"写了但没接线"的死代码比 bug 更可怕：表面有兜底，实际没有。

## 收获

1. 调用 LLM 后必须做**结构性回读**，别只看"调用成功"
2. 宁可兼容字段漂移（别名映射），也不要赌提示词约束 100% 生效
3. 写完兜底/降级逻辑，回头查一遍主流程是否真的调用了它
